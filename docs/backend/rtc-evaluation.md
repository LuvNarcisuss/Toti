# Toti RTC audio/video integration evaluation

## Current state

Toti currently stores Voice room membership and text messages online, but it has no RTC provider, token service, signaling configuration, or media acceptance. `TotiBackendConfiguration.rtcEnabled` must remain `false` until the dependencies below are delivered and accepted.

## Provider options

### Recommended: LiveKit Cloud or self-hosted LiveKit

LiveKit provides a Swift SDK for iOS audio, video, and data, and supports both LiveKit Cloud and self-hosting. Its production authentication model uses a backend-issued JWT containing participant identity, room name, and publish/subscribe grants. The iOS SDK requires camera and microphone usage descriptions; its audio-session behavior and reconnection lifecycle must be integrated with the existing UIKit `CallController`.

Official references:

- Swift quickstart: https://docs.livekit.io/transport/sdk-platforms/swift/
- Token and grants: https://docs.livekit.io/home/server/generating-tokens
- Authentication and token endpoints: https://docs.livekit.io/home/concepts/authentication/
- Swift SDK: https://github.com/livekit/client-sdk-swift

Why it fits Toti: the project already has Swift Package Manager, UIKit, AVFoundation, room IDs, authenticated Supabase membership, and a clear need to keep provider credentials off the client. LiveKit Cloud reduces initial infrastructure work; self-hosting preserves more deployment control but adds TURN, observability, upgrades, and incident response.

### Agora

Agora's iOS RTC SDK is a mature managed option. It also requires a server-side token service; the token is scoped to a channel and privileges and has a maximum validity window. The provider would add an App ID, App Certificate, token endpoint, channel lifecycle, and native SDK integration.

Official references:

- Token server: https://docs.agora.io/en/realtime-media/rtc/build/authenticate-users/deploy-token-server
- Authentication: https://docs.agora.io/en/realtime-media/rtc/build/authentication/authentication

Tradeoff: strong managed media infrastructure, but a separate provider-specific channel/token model and SDK integration from the current UIKit room abstraction.

### Twilio Video

Twilio Video supplies an iOS SDK with Rooms, Participants, LocalTracks, and RemoteTracks. Every participant needs a short-lived Access Token generated by a backend server. Camera/microphone permission handling, reconnect callbacks, room lifecycle, and optional CallKit/Push integration are required.

Official references:

- iOS quickstart: https://www.twilio.com/docs/video/ios-getting-started
- Application components and token server: https://www.twilio.com/docs/video/video-app-components
- Access Tokens: https://www.twilio.com/docs/video/tutorials/user-identity-access-tokens

Tradeoff: clear primitives and managed rooms, but the product would adopt Twilio-specific Room/Track semantics and credentials in addition to Supabase.

## Required Toti configuration and implementation

1. Select the provider and create a project in a region appropriate for Toti users. Keep provider API secrets outside the app and repository.
2. Add the pinned iOS SDK through `TotiMusic/project.yml` and retain the Swift 5 / iOS 16 floor.
3. Add a Supabase Edge Function or separately managed token endpoint that:
   - validates the current Supabase Guest JWT and session/account state;
   - checks the Toti room exists, the caller is an active member, and both-direction blocks do not deny access;
   - maps the Toti room UUID to the provider room/channel name;
   - issues a short-lived token scoped to the caller identity and room;
   - never exposes the provider API key, secret, or signing key.
4. Add provider URL, token endpoint, and feature flags to owned configuration. Do not put provider secrets in `TotiIdentity` or `Info.plist`.
5. Replace the online unavailable guard in `CallController` with an explicit call session object that handles join, leave, reconnecting, connected, failed, muted, camera-off, and revoked-membership states.
6. Add `NSCameraUsageDescription` and `NSMicrophoneUsageDescription` with Toti-owned English purpose text. Configure background audio only if the product explicitly supports background calls; add CallKit and APNs only if incoming background calls are required.
7. Persist no provider token or raw media credentials in the local archive. Clear media state on account generation changes and room leave.

## Required acceptance before enabling `rtcEnabled`

- Two disposable Guests join the same room and publish/subscribe audio.
- Two disposable Guests publish/subscribe camera video and see the correct remote participant.
- Mute/unmute, camera on/off, speaker route, permission denial, and interruption recovery work.
- Room capacity, block relationships, membership removal, leave, room closure, and revoked Supabase sessions prevent or end provider access.
- Token expiry/refresh, reconnect after network loss, app background/foreground, and process termination are handled.
- No audio/video UI reports success before provider acknowledgement, and no unavailable state remains after a successful connection.
- Toti UI Acceptance and at least one physical iPhone cover the call matrix; iOS 16 behavior is explicitly recorded.

Until this matrix passes, Voice remains a real online text room with an honest unavailable RTC state.
